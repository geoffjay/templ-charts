# templ-charts — Implementation Plan (v5)

## 1. Vision

v1–v3 built the framework and reached **full nivo SVG chart parity** (28 chart
families). v4 took the library **from complete to consumable**: render helpers,
runnable examples, an honest prop surface, benchmarks, and a per-chart showcase.

Along the way v4 was deliberately disciplined — it fixed *dishonest* props by
**removing** the features they advertised rather than building them, and it
consolidated every gap into [`docs/plans/tracking.md`](tracking.md). The
result is a library that is honest and pleasant to consume, but one where a
handful of charts still render **subtly wrong** output, ~25 charts advertise
motion they don't deliver, and several charts ship fewer layers/interactions
than their nivo counterparts.

**v5 is the "fidelity & finish" release.** It closes the last mile of the
**SVG** story so that every chart templ-charts ships is *correct*, *complete*,
and *animated* — matching nivo's SVG behaviour, not just its static shape. It
adds **no new chart types** and **no new d3 modules**; all work is completing,
correcting, and animating charts that already exist, plus finishing two partial
d3-geo clips.

v5 deliberately stops **short of the Canvas rendering path and the large-N
performance work** (Barnes–Hut, delaunator, streaming render). Those two are the
single largest remaining nivo capability, they pair together, and they are the
natural theme for their **own** release (v6). Everything v5 does — animation,
zoom, correct geo, unified hover — is layout/output work that a future Canvas
backend will *reuse*, so finishing it first is the right order.

v5 stays **SVG-only** and follows the same per-package anatomy, verbatim
defaults, and golden-test discipline as v1–v4. See [`docs/plans/v1.md`](v1.md),
[`docs/plans/v2.md`](v2.md), [`docs/plans/v3.md`](v3.md), and
[`docs/plans/v4.md`](v4.md) for the prior structure this document mirrors,
and [`docs/plans/tracking.md`](tracking.md) for the backlog it draws from.

## 3. Correctness — geo `clipCircle` + `clipExtent`

**This is the one v5 item that fixes *wrong* output**, and it leads the release.

Today `internal/d3/geo` ships only `clipAntimeridian` (the full generic clip
framework — `clip.go`, `clip_helpers.go`, `rejoin`/`buffer`/`polygonContains`).
The azimuthal family (`orthographic`, `gnomonic`, `stereographic`,
`azimuthalEqualArea`, `azimuthalEquidistant`) therefore renders the **whole
sphere** and can draw far-side geometry over the near hemisphere — a real
correctness gap, documented at `internal/d3/geo/projections.go:10,71`,
`projection.go:10`, `math.go:10-14`, and `docs/NOTES.md` (v3 Phase 7).

- **`clipCircle(radius)`** — the small-circle preclip d3-geo uses for the
  azimuthal family. Port d3-geo's `clip/circle.js`: the visible/invisible test,
  the circle-intersection interpolation, and the code-point line clipper, wired
  into the existing generic `clip` framework exactly as `clipAntimeridian` is.
  Each azimuthal projection gets its clip angle (`orthographic` = 90°,
  `gnomonic`/`stereographic`/azimuthal* = their d3 defaults / `π`).
- **`clipExtent([[x0,y0],[x1,y1]])`** — the rectangular post-clip
  (`projection.go:10` "clipExtent omitted"). Port d3-geo's `clip/rectangle.js`;
  needed for correct viewport cropping and a prerequisite for a clean geo demo.
- **Risk**: the circle interpolator and the intersect math are the fiddly parts
  (the same class of bug as the v3 antimeridian `NaN`-seed noted in NOTES.md).
  Golden-test projected path strings for each azimuthal projection against
  d3-geo v3 output, and add a unit test asserting far-side points are dropped.
- **Out of scope (still deferred, §11)**: `GeoPath` bounds/area/centroid,
  `fitExtent`/`fitSize`, projections beyond the ~10 nivo exposes, TopoJSON.

After this, all ten nivo projections render correctly, closing the v3 §11 /
deferred §6 correctness item.

## 4. Animation parity (the largest v5 workstream)

Animation is genuinely **v1-only**: only bar (`bar_item.templ:151`), line
(`lines.templ:39`), and pie/arc (`arc_shape.templ:66`) emit SMIL `<animate>`.
v4 correctly *removed* the dead `core.MotionProps{Animate:true}` embed from the
25 non-animating charts rather than leaving a lie in the surface. v5 puts motion
**back** — this time actually rendered.

### 4.1 Approach
- Re-introduce the `Animate bool` + `MotionConfig` prop on each chart, but only
  where v5 wires it to a rendering primitive (no repeat of the v1→v4 dishonesty).
  Default **`Animate:false`** so every existing golden stays byte-stable and
  static/zero-JS embeds are unchanged.
- Reuse the three existing primitives — SMIL `<animate>` on the geometry
  attribute that "grows" the shape, plus scoped CSS keyframes for opacity/fade,
  gated exactly like `rects.RoundedRect` and `arcs.ArcShape` already do.
- Implement **by geometry family**, not chart-by-chart, so each primitive is
  written once and shared:

| Family | Charts | Enter transition (mirrors nivo) |
|---|---|---|
| **rects** | heatmap, waffle, treemap, icicle, bullet, marimekko, boxplot | grow from 0 w/h or fade opacity (reuse `rects.RoundedRect` SMIL) |
| **arcs** | radial-bar, polar-bar, sunburst, chord | grow outer radius from inner (reuse `arcs.ArcShape` `transitionMode`) |
| **lines/areas** | radar, stream, funnel, parallel-coordinates, bump | animate `d` / area baseline (reuse `line` `<animate>` on `d`) |
| **circles** | scatterplot, swarmplot, circle-packing, network | scale `r` 0→size, staggered |
| **cells/paths** | calendar, sankey, geo | fade-in (opacity keyframes); sankey link `stroke-dashoffset` draw-on |

- **Stagger**: honour the props that already exist for it (`waffle.motionStagger`)
  and add per-family stagger where nivo does (bar/heatmap index-based delay) via
  SMIL `begin="{i*stagger}s"`.
- **Size**: medium-large but low-risk — the primitives exist; the work is
  threading `Animate` through each chart's props → `Use{Chart}` → templ and
  computing the from/to geometry. Grouping by family keeps it ~5 shared
  implementations, not 25.

### 4.2 Tests
- Goldens stay byte-stable at the default (`Animate:false`).
- One **animated** golden per family (5 snapshots) asserts the `<animate>` /
  keyframe markup is emitted with the right attributes, mirroring how bar/line/
  pie animated output is already snapshotted.

## 5. Partial-chart completions

Three charts ship a subset of their nivo layers. Each is small and well-scoped;
the geometry primitives already exist.

- **waffle `areas` polygon layer** (`charts/waffle/types.go:6,61-69`,
  `render.go:75`). Only `cells`/`legends` layers exist. `charts/grid` already
  ships `GetCellsPolygons`/`PerpendicularPolygon`/`AreBoundingBoxTouching`
  (built in v1, exercised by waffle cells in v2) — v5 uses them to emit the
  per-datum outline polygon `areas` layer nivo ships, and adds `areas` to
  `DefaultLayers`.
- **calendar month outline-path border** (`charts/calendar/types.go:7,94`
  region, `render.go:52`). v4 gated the dead `MonthBorderColor/Width` props;
  v5 re-adds them backed by the real month **outline path** — the boundary walk
  around each month's day cells (d3-time month bucketing over the existing
  ported time scale). Emit `<path fill=none stroke=monthBorderColor
  stroke-width=monthBorderWidth>` per month.
- **sankey link gradients** (`charts/sankey/types.go`, v4 removed the dead
  `EnableLinkGradient`). Re-add `EnableLinkGradient`, backed by a per-link
  `<linearGradient>` in `<defs>` (source-color → target-color along the link's
  x extent) via the existing `core` gradient defs, referenced by the link path's
  `fill`/`stroke`. Matches `@nivo/sankey`'s `enableLinkGradient`.

Each gets a golden (default off; on-variant snapshot) and a demo variant.

## 6. Interactivity completions

No new interaction *model* — extend v2's `charts/interact` client layer and the
HTMX state path. Four gaps from deferred §4:

- **Unified hover-others dimming.** Today chord uses a scoped CSS `:has()`
  `<style>` block (`charts/chord/render.go:99-156`); network has none; sankey's
  is deferred. v5 lifts chord's proven pattern into a **shared helper** (in
  `charts/interact` or a small shared render helper) that emits the resting-
  opacity + `:has(...:hover)` dim/relight rules given a set of entity classes,
  and applies it uniformly to **sankey** (dim other nodes/links → `nodeHoverOthersOpacity`/
  `linkHoverOthersOpacity`, already in the prop surface) and **network** (dim
  unconnected nodes/links → `activeNodeSize`/`inactiveNodeSize`). Pure client
  CSS, no server round-trip; degrades to no-op when non-interactive.
- **Client-driven zoom / drill-down** for **icicle, treemap, circle-packing,
  sunburst** (deferral comments in each `types.go`). Layout math is present; v5
  adds the client interaction: click a node → recompute the visible sub-tree's
  transform and re-render (HTMX fragment swap through the existing `Registry`,
  since it changes *what* is rendered — consistent with the v2/v3 client-vs-HTMX
  split). Add `EnableZooming` handling (icicle already declares it) and a
  breadcrumb/back affordance. Static render unchanged when zoom is off.
- **Retire the line per-mousemove fallback.** `charts/line/mesh.templ:64` still
  emits `hx-trigger="mouseenter, mousemove throttle:40ms"` (a full server SVG
  re-render per move) as the no-JS fallback; `ClientHover` already replaces it
  client-side. v5 makes `ClientHover` the default (or removes the server
  mousemove path), keeping only the coarse mouseenter/leave server hook for the
  genuinely-JS-disabled case. Closes the original v1 NOTES.md item.
- **`ResizeObserver` re-fetch** (deferred §4, absent in
  `charts/interact/script.go`). Add an **opt-in** observer that, on container
  resize, re-fetches an axes-heavy chart for a pixel-accurate re-render (tick/
  label density). Cosmetic fluid scaling stays covered by the `Responsive`
  viewBox prop; this is the accuracy upgrade for axis-dense charts, gated by a
  new `data-tc-observe` attribute so it costs nothing unless opted in.

## 7. Test depth

v4 polish already lifted 14 of the 15 single-golden charts to two snapshots; the
audit's deferred §9 is largely closed. v5 finishes it:

- **network** is the last chart at a single golden — add a variant (e.g.
  different link distance / node sizing) to match the rest.
- Add the **animated-variant** goldens (§4.2, five family snapshots) and the
  **on-variant** goldens for the §5 completions (waffle areas, calendar month
  border, sankey gradient) and §3 azimuthal geo.
- Extend the `internal/d3/geo` port tests with `clipCircle` far-side-drop
  assertions and per-azimuthal-projection path goldens (§3).

## 8. Build / test

- **Golden discipline unchanged.** All existing goldens stay byte-stable
  (animation defaults off; completions default off). New behaviour is asserted
  by *new* on-variant snapshots via `internal/golden.Assert`; `make golden`
  extended to any newly golden-owning path.
- **Port tests**: `clipCircle`/`clipExtent` unit + path goldens vs d3-geo v3
  (§3), following the v3 geo golden strategy (3-decimal rounding, Go-generated
  snapshots, coordinates unit-checked against known d3 output).
- **Examples**: keep every chart's `ExampleXxx` compiling; add animated/zoom
  examples where they clarify the new props.
- **Regenerate** only the snapshots the new *default-on* changes touch (none
  expected — defaults are off), and document any deliberate regen in NOTES.md.
- CI unchanged: `make ci` (`make lint` + `make test`) stays green; `make bench`
  (from v4) still excluded from CI.

## 9. Demo app — `examples/app`

Extend the existing app and the v4 detail-page registry
(`handlers/entries`) rather than adding new plumbing:

- **Animation**: an "Animate" toggle on the detail page (`/chart/{slug}?animate=1`)
  that flips the chart's `Animate` prop through the existing Render closure —
  showing the new motion across families for free.
- **Zoom**: make the icicle/treemap/circle-packing/sunburst detail pages
  interactive (click-to-zoom, breadcrumb), wired through the `Registry`.
- **Completions**: demo variants for waffle `areas`, calendar month borders, and
  gradient sankey.
- **Geo**: add an **azimuthal** (orthographic/globe) variant to the geo page to
  showcase the §3 `clipCircle` fix, alongside the existing mercator map.
- **Hover-others**: enable the unified dimming on the sankey and network pages.

## 11. Scope summary for v5

**Correctness**: geo `clipCircle` (+ `clipExtent`) — all ten projections now
render correctly.

**Animation**: a wired `MotionProps`/`Animate` threaded (default off) into the
~25 v2/v3 charts via five shared geometry-family primitives; SMIL `<animate>` +
scoped CSS keyframes.

**Completions**: waffle `areas` polygon layer, calendar month outline-path
border, sankey link gradients — the three shipped-partial charts finished.

**Interactivity**: shared hover-others dimming (sankey/network/chord), client
zoom/drill-down (icicle/treemap/circle-packing/sunburst), retired line
per-mousemove fallback, opt-in `ResizeObserver` re-fetch.

**Tests/demo**: network second golden + animated/on-variant/azimuthal goldens;
detail-page animate toggle, zoom, and the new completion/geo variants.

**Explicitly out of scope** (→ §12 / [`tracking.md`](tracking.md)):
Canvas rendering path, large-N performance (Barnes–Hut, delaunator, streaming
render), HSL/Lab/Lch color spaces, public sample-data export, `charts/static`
registry extension to all 28, unified color-setting API, full geo projection
catalog + `GeoPath` bounds/centroid/`fitExtent`, TopoJSON.

## 12. Explicitly deferred (v6+)

After v5, the remaining nivo gap is concentrated in **one theme**:

- **Canvas rendering path + large-N performance — the v6 theme.** nivo's
  `*Canvas` variants for large-N datasets, plus the quadratic-algorithm
  optimizations that make them worthwhile: Barnes–Hut quadtree for
  `internal/d3/force` (`manybody.go`/`collide.go` are O(n²)), a delaunator/
  sweep-hull replacement for `internal/d3/delaunay` (O(n²) Bowyer–Watson), and a
  streaming/large-N SVG-build story (~585 `WriteString` calls today). These pair
  together and are the natural next release; v5's animation/layout work is
  reused by a Canvas backend.
- **Color spaces** — `internal/d3/color` stays RGB-only; add HSL/Lab/Lch only
  when a chart needs perceptually-uniform interpolation.
- **Consumption surface** — public typed sample-data export, `charts/static`
  registry extension to all 28 charts, and a single unifying color-setting API
  (v4 documented the five shapes; unification remains deferred).
- **geo completeness beyond correctness** — `GeoPath` bounds/area/centroid,
  `fitExtent`/`fitSize`, projections beyond the ~10 nivo exposes, TopoJSON.

The consolidated backlog remains [`docs/plans/tracking.md`](tracking.md);
v5 removes from it the geo `clipCircle`/`clipExtent` correctness item (§6),
animation parity (§3), the partial-chart completions (§5), the interactivity
gaps (§4), and the test-depth item (§9), leaving Canvas + large-N (§1–2), color
spaces (§7), and the consumption surface (§8) as the standing remainder.
